The form submits to the list plugin on the target page, in the argument shape of the list's own filter form: `tx_academicprograms_programlist[demand][filterCollection][]` with one category uid each. The list answers the POST with a redirect to its filtered URL. `listUri` is empty without a target page that can be linked, and `filterTypes.visible` without a category type that has categories: either way there is nothing to offer, so no form renders. The "All" option, the options without results and the UpperCamelCase `extensionName` follow the filter of the list, see `Program/DemandCategories.html`; the finder shows every filter type, it has no "More filters". The module `program-finder.js` narrows the options in the browser and is driven by data attributes alone, so an override keeps it working by keeping them. On the form, `data-academic-programs-finder-programs` carries the programs as JSON, and `data-academic-programs-finder-count-one` and `data-academic-programs-finder-count-other` the patterns of the count sentence. `data-academic-programs-finder-select` marks each category select, `data-academic-programs-finder-count` the element whose text becomes the count sentence, and `data-academic-programs-finder-status` an empty `role="status"` element that announces a changed count. Without the module the button keeps its plain label and the status element stays empty.
