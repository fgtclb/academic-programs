The active filters of the program list, as tags, and the link that resets them. Every tag links to the list with its category removed, every other category and the sorting kept. Without a category left the link carries the sorting alone, which still counts as a selection: only a request without any demand argument applies the categories the content element presets, so the visitor does not get a preset category back that they removed. The reset link leads to the page without any argument, so the list shows what the content element presets. It is offered while the list shows a visitor's selection, `visitorSelection`, and a category is selected or the content element preselects one, also once the visitor removed the preselected one. On the bare page it would lead to what is already shown, and with nothing selected and nothing preselected it would reset nothing but the sorting or the page. Only categories of the types the collection was built for get a tag, which are all of them for the collections the demand factories build. A collection a demand listener builds by hand without type identifiers gets no tags. The tags follow the type order of the category group, the order of the filters. The loop reads `allCategoriesByType` rather than the category collection itself: the collection is an iterator with a single position, and `ct:filterArgument` walks the same collection inside the loop, which would end the loop after the first tag. Arguments: the "SortingAndFilters" partial renders it with "{_all}". - demand: the demand of the list shown - settings: for `filter.showActiveFilters` and `filter.showReset` - visitorSelection: whether the request carried a demand
