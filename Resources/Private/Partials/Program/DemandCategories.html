`filterTypes.visible` holds the category types to offer right away, in the order to offer them, and only types with categories: the filter types of the element or the site, or every type of the group with categories when neither sets any. `filterTypes.more` holds the ones after `settings.filter.visibleCount`; they go into a "More filters" disclosure, which is open while one of them has a value. Without `filterTypes` - a project controller that overrides `listAction()`, or a template that renders this partial with arguments of its own - every type with categories is offered in the type order of the group, as before the filter types existed.
{f:translate(key: 'filter.moreFilters', extensionName: 'AcademicPrograms')}
The "All" option reads `sys_category.programs.allOptions.` and falls back to the label every filter shares when a type has none of its own. `extensionName` is the UpperCamelCase name on purpose: up to TYPO3 v13, `_LOCAL_LANG` is read from `plugin.tx_` and the lowercased name as given, so `academic_programs` would look in `plugin.tx_academic_programs` instead of `plugin.tx_academicprograms`. TYPO3 v14 strips the underscore and reads the same path either way.
